# stock-daily-briefing

장 마감 브리핑 웹페이지를 매일 자동으로 만드는 프로젝트입니다. 국내(코스피·코스닥)와
미국(S&P500)을 상단 탭으로 오가며 볼 수 있습니다.
장 마감 후부터 다음날 개장 전까지 아무 때나 열어보도록 만들었습니다.

> 자동으로 만들어진 참고 자료이며 투자 권유가 아닙니다.
> 종목 선정은 과거 가격과 거래량에서 계산한 기계적 조건에 따른 것으로 수익을 보장하지 않습니다.

## 화면 구성

0. **국내 시장 / 미국 시장 / 주요 이슈 탭** — 미국·이슈 탭은 처음 누를 때만
   `us.json` / `issues.json`을 받아옵니다
1. **지수** — 종가, 등락, 최근 추이 (국내: 코스피·코스닥 / 미국: S&P500·나스닥·다우)
2. **오늘의 시장** — 지수 요약과 상승·하락 종목 수
3. **주요 뉴스**
4. **주요 종목** — (국내는 코스피/코스닥으로도 구분) × 기준(거래대금 상위/등락률 상위)
5. **내일 주목할 종목** — 조건을 충족한 종목과 그 근거
6. **검색** — 종목명이나 코드로 즉시 검색, 누르면 차트·회사 정보·뉴스 (현재 탭의 시장 안에서만 검색)
7. **주요 이슈** — 지수·환율·금리·해외 증시 등 시장 전체 흐름을 제목·요약·출처·링크로.
   장 마감과 무관하게 3시간마다 따로 갱신됩니다 (날짜 개념이 없어 지난 날짜 페이지에는 안 나옵니다)

## 데이터 출처

| 항목 | 출처 | 키 |
|---|---|---|
| 국내 전 종목 시세·시가총액 | 네이버 금융 | 불필요 |
| 국내 종목별 일별 시세(차트) | 네이버 금융 | 불필요 |
| 코스피·코스닥 지수 | 네이버 금융 | 불필요 |
| 코스피·코스닥 개인·외국인·기관 순매수 | 네이버 금융(모바일) | 불필요 |
| 국내 뉴스 | 네이버 검색 API (실패 시 구글 뉴스 RSS) | `NAVER_CLIENT_ID`, `NAVER_CLIENT_SECRET` |
| 국내 회사 개요(업종·설립연도·대표자) | DART 전자공시 | `DART_API_KEY` |
| S&P500 구성종목 목록·업종(GICS) | GitHub `datasets/s-and-p-500-companies` | 불필요 |
| 미국 종목별 시세·차트 | 야후 파이낸스(`v8/finance/chart`, 비공식) | 불필요 |
| 미국 지수(S&P500·나스닥·다우) | 야후 파이낸스 | 불필요 |
| 미국 뉴스 | 구글 뉴스 RSS(영문) | 불필요 |

키는 GitHub Secrets에 넣습니다. 없어도 해당 항목만 빠지고 나머지는 정상 동작합니다.

**주의** — KRX 공식 API는 로그인을 요구하도록 바뀌어 쓰지 않습니다. 네이버 금융과 야후
파이낸스 모두 공식 API가 아니라 언제든 구조가 바뀔 수 있어, 수집부(`app/naver.py`,
`app/yahoo.py`)만 고치면 되도록 분리했습니다. 야후의 배치 시세·회사 개요 엔드포인트는
인증(crumb)을 요구해 막혀 있어, 종목별 일별 시세 엔드포인트로 대신합니다.

국내와 미국은 마감 시각도, 크론도, 코드도 서로 완전히 독립적입니다.

- **국내 (`app/kr_build.py`)**: 평일 16:40 KST — 코스피·코스닥 마감 직후. 결과를
  `cache/kr_latest/`에 씁니다.
- **미국 (`app/us_build.py`)**: 평일 07:00 KST — 미국 장은 서머타임에 따라 한국시간
  05~06시에 끝나므로 그보다 충분히 뒤입니다. 결과를 `cache/us_latest/`에 씁니다.
- **이슈 (`app/issue_build.py`)**: 3시간마다 — 뉴스는 장 마감과 무관하게 하루 종일
  움직입니다. 결과를 `cache/issue_latest/`에 씁니다.

세 모듈 다 서로를 import하지 않고, 서로의 존재를 모릅니다. 실제 배포 화면(`dist/`)은
`assemble.py` 하나가 두 캐시를 그대로 갖다 붙여서 만듭니다 — 국내·미국 중 하나가
아직 없거나 실패해도 있는 쪽만 나갑니다. GitHub Pages·Cloudflare Pages는 배포할 때마다
사이트 전체를 통째로 새로 올리는 방식이라(부분 갱신이 안 됨), 두 워크플로 모두
"자기 시장만 새로 받고 → assemble.py로 dist/ 전체를 다시 조립해서 → 통째로 배포"하는
같은 절차를 따릅니다. `assemble.py --archive`(국내 워크플로 전용)만 그날치를 날짜별
아카이브에 정식으로 남기고, 미국 쪽 아침 갱신은 아카이브를 건드리지 않습니다 — 그날의
국내 장이 아직 실제로 열리지 않았기 때문입니다 (오후 국내 빌드 때 그날치로 정식
아카이브됩니다).

## 실행

```bash
pip install -r requirements.txt
python run_kr.py     # cache/kr_latest/ 생성 (국내만)
python run_us.py     # cache/us_latest/ 생성 (미국만)
python run_issues.py # cache/issue_latest/ 생성 (시장 이슈만)
python assemble.py --archive   # 위 둘을 dist/로 합치고 오늘자 아카이브에 기록
# 또는 로컬에서 한 번에:
python build.py      # run_kr + run_us + assemble --archive
```

자동 실행은 평일 16:40 KST(`.github/workflows/daily.yml`, 국내)와
평일 07:00 KST(`.github/workflows/us-morning.yml`, 미국)이며, `daily.yml`은
Actions 탭에서 수동 실행 시 차트를 준비할 종목 수를 지정할 수 있습니다.

## 설정 (환경변수)

| 변수 | 기본값 | 설명 |
|---|---|---|
| `CHART_LIMIT` | 800 | 차트를 준비할 종목 수 (거래대금 상위순) |
| `CHART_DAYS` | 60 | 차트에 담을 거래일 수 |
| `TOP_N` | 10 | 목록에 보여줄 종목 수 |
| `WATCH_N` | 4 | 내일 주목할 종목 수 |
| `MIN_VALUE` | 10억 | 당일 거래대금 하한(원) |
| `MIN_MARKET_CAP` | 500억 | 시가총액 하한(원) |

## 구성

```
run_kr.py             국내 빌드 실행 (daily.yml 전용 진입점)
run_us.py             미국 빌드 실행 (us-morning.yml 전용 진입점)
run_issues.py         시장 이슈 수집 실행 (issues.yml 전용 진입점)
assemble.py           국내·미국 캐시를 dist/로 합침 — 둘을 동시에 아는 유일한 파일
build.py              로컬에서 국내+미국을 한 번에 만들어보는 편의용 (배포에는 안 씀)
watchdog.py           배포된 사이트가 오늘 것인지 확인하고, 아니면 빌드를 다시 띄움
app/kr_build.py       국내 수집 → 계산 → cache/kr_latest/ 생성. 미국을 전혀 모름
app/us_build.py       미국 수집 → 계산 → cache/us_latest/ 생성. 국내를 전혀 모름
app/issue_build.py    시장 전체 이슈 수집 → cache/issue_latest/ 생성. 국내·미국을 전혀 모름
app/naver.py          네이버 금융 수집 (국내 시세·지수·일별시세)
app/yahoo.py          야후 파이낸스 수집 (미국 시세·지수·일별시세) + S&P500 목록
app/news.py           뉴스 수집. locale="ko"면 네이버 API → 구글 RSS, "en"이면 구글 RSS(영문)
app/dart.py           DART 기업개황 + 캐시 (국내 전용)
app/indicators.py     이동평균·RSI·거래대금 급증·신고가 (국내·미국 공통)
app/picks.py          내일 주목할 종목 선정과 근거 생성. currency="USD"면 상한가 과열 감점을 끔
app/template.html     화면. 상단 탭으로 국내(D=window.__DATA__)/미국(us.json) 데이터를 바꿔 낍니다
```

## 설정 (환경변수, 미국)

| 변수 | 기본값 | 설명 |
|---|---|---|
| `US_CHART_LIMIT` | 503 | 시세를 조회할 S&P500 종목 수 (배치 조회가 막혀 있어 종목마다 개별 호출) |

## 자동 점검·복구 (watchdog)

GitHub의 예약 실행(`schedule`)이 이 저장소에서는 제때 뜨질 않습니다. 실측
(2026-08-24~09-09)으로 국내 빌드는 목표보다 **0.7~11.9시간**, 미국 빌드는
**0.3~7.9시간** 늦게 시작됐습니다. 빌드는 멀쩡히 성공하는데 몇 시간 뒤에야 도는
탓에, 정작 열어보는 시간대엔 아직 어제 데이터가 떠 있는 일이 반복됐습니다.

`watchdog.yml`은 30분마다 돌면서 **배포된 사이트를 직접 열어보고** 오늘 것이
아니면 해당 빌드를 다시 띄웁니다.

- 판단 기준은 화면에 찍히는 `builtAt`(데이터 생성 시각)입니다. 거래일이 아니라
  "빌드가 돈 날"이라, 국내 휴장일에도 한 번 돌고 나면 조용해집니다.
- 다시 띄울 때는 `workflow_dispatch`를 씁니다 — 예약과 달리 **지연 없이 즉시**
  실행됩니다. 워치독 자신의 예약도 늦을 수 있어 30분 간격으로 촘촘히 걸어두고,
  그중 가장 먼저 도착한 실행이 복구를 맡습니다.
- 이미 돌고 있거나 45분 안에 돈 빌드가 있으면 다시 띄우지 않습니다(중복 방지).
- 이슈는 날짜가 아니라 "얼마나 묵었나"로 봅니다(5시간). 3시간마다 도는 흐름이라
  날짜 비교로는 하루 종일 묵어도 못 잡기 때문입니다.
- 사이트를 아예 못 읽었을 땐 아무것도 하지 않습니다 — 일시적 네트워크 문제로
  빌드를 계속 걸어대는 쪽이 더 나쁘기 때문입니다.

정확한 시각까지 맞추려면(예: 반드시 16:40 정각에) GitHub 예약 대신 외부에서
`workflow_dispatch`를 호출하는 방법밖에 없습니다. 워치독은 그 대신 "늦어도
알아서 따라잡는" 쪽을 보장합니다.
